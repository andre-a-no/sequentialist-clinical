# sequentialist-clinical

Промежуточный мониторинг клинических испытаний (`sequentialist.clinical`):
спецификации `clinical.trial/1`, групповые последовательные планы (по
умолчанию) и anytime-valid тесты, анализы на дату отсечения, отчёты DSMB
(открытая и закрытая части), протоколы анализов, чтение CDISC ADaM.
Версия 0.1.0, не опубликована.

## Постоянные правила

- **Статистика — только в ядре.** Ядро и sequentialist-core из этого
  репозитория не править. Чего не хватает — список запросов: что нужно,
  зачем, какой интерфейс. Запрос к core — то, что нужно хотя бы половине
  прикладных пакетов; что уже в core, обратно не выносится.
- **Гарантии.** Каждый вывод называет свою гарантию (`exact`, `asymptotic`,
  `model`, `approximate`, `none`) так, как её объявляет процедура ядра.
  Утверждения честные и сдержанные; ничего не обещать без проверки тестом.
  Соответствие 21 CFR Part 11, ICH E9, GCP не заявлять.
- **Сверка с эталонами.** Каждая процедура и каждый результат сверяются с
  внешней эталонной реализацией или закрытой формулой, где она есть.
  Эталоны пишет `tools/make_references.py` (scipy, lifelines — только там).
- **Python ≥3.8**, обязательных зависимостей, кроме ядра и core, нет.
  Перед пушем: `ruff check .`, `mypy`, тесты, `vermin -t=3.8-`; CI должен
  быть зелёным.
- **Лицензии:** AGPL-3.0-only или коммерческая (COMMERCIAL.md); в каждом
  исходном файле SPDX-заголовок без города.
- **Чужой код принимается только по CLA** (`CLA.md`). В CLA нет оговорки
  о подсудности и нет города — так решил владелец.
- **Контакты** в публичных файлах — только email: a.hobukob@gmail.com,
  andrei@hobukob.ru. Никаких телефонов, адрес компании не указывать.
- **Никаких идентификаторов моделей** в коммитах, PR и коде.
- **Персональные данные:** 152-ФЗ и GDPR; только псевдонимы (`USUBJID`
  заменяется при чтении ADaM), агрегаты в открытых отчётах.
- PR — только по просьбе владельца; ничего не мержить без его явного
  подтверждения.
- Общение с владельцем — по-русски; код, документация и коммиты —
  по-английски.

## Особенности этого репозитория

- ТЗ 0.1 согласовано с владельцем: начать с испытаний; оба типа плана,
  групповой по умолчанию; ADaM из CSV и Dataset-JSON, XPT — позже.
- Анализ — команда `analyse` с датой отсечения: снимок данных проходит
  через свежий запуск процедуры ядра (поток `data`), групповой план —
  через `GroupSequentialMonitor` (поток `monitor`). Пересечение границы
  записывается, но ничего не останавливает: рекомендует DSMB, решает
  спонсор.
- `Run` ядра молча пропускает некорректные входы (`on_invalid="skip"`), а
  `Stream` core это не настраивает; поэтому анализ проверяет, что поток
  принял все входы снимка.
- Тестовые данные: пилот CDISC (`tests/data/cdiscpilot01`, MIT, CDISC).
  Наборы `colon` и `pbc` пакета survival (LGPL) не включены: владелец не
  решил вопрос о сочетании LGPL с коммерческой лицензией.
- Пороги и умолчания, ещё не подтверждённые владельцем: скрытие малых
  ячеек `small_cells` = 5.
- Публикация — `.github/workflows/publish.yml`, как в sequentialist-core:
  Trusted Publishing, издатель на PyPI — владелец `andre-a-no`,
  репозиторий `sequentialist-clinical`, workflow `publish.yml`, environment
  `pypi`. Запускается публикацией GitHub-релиза или вручную с указанием
  тега; тег должен быть `v` + версия из `version.py`. Публикация
  останавливается, пока sequentialist-core нет на PyPI.

## Ограничения 0.1 (описаны в README)

- Две группы; нет адаптивной рандомизации, пересчёта объёма, условной
  мощности.
- Нет скорректированных оценок эффекта после группового плана; в отчёте
  описательные числа по группам с гарантией `none`.
- Связанные времена событий ядро разбирает по одному (не по Бреслоу).
- Состояние испытания (все пациенты) пишется целиком на каждой
  контрольной точке.

## Запросы к ядру (не выполнены)

1. Скорректированные оценки после группового плана: медианно-несмещённая
   оценка, интервал и p-значение по упорядочению по этапам —
   `GroupSequentialDesign.adjusted(stage, z)`.
2. Условная и прогностическая мощность — `conditional_power(design, stage,
   z, drift)`.
3. Оценка отношения рисков у `GroupSequentialLogRank` вне плановых
   анализов (сейчас — только в выходе анализа).
4. MaxSPRT (пуассоновский и биномиальный) с критическими значениями,
   сверка с R-пакетом `Sequential` — для `clinical.safety/1`.
5. CUSUM с поправкой на риск пациента (Steiner et al., 2000) и его ARL —
   для `clinical.care/1`.
6. Anytime-valid сравнение двух средних.
